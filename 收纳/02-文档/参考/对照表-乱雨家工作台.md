# 对照表 · 乱雨家工作台 vs 我们这套

读于 2026-11-19。原文在 `luanyujia-workbench\`（20.7 MB，只看不版本化）。
只读了两块：`02-会话定位与跟随`、`05-协作与规矩`，其余没动。

> 结论先放：**三样该抄，两样该改，三样别抄。** 全部加起来不超过 4 小时，不需要装任何东西。

---

## 一、该抄（便宜、马上能用）

### 1. 用会话 id 认领身份，别用标题

- **他们**：三条硬结论的第一条——「必须给会话 id，不能只靠标题认人：标题会重名、会差一个空格、会被改名」。
  认领四步：会话 ID → 场景索引表 → 定位卡 → 场景记忆。
- **我们**：定位卡现在**按标题匹配**（`bluefish-persona` 拿 `sessionTitle` 去配文件名）。
  标题一改名、一重名，就配不上——而且**不报错，安静地不注入**。
- **判断**：抄。他们的失败模式和我们写的那句注释一模一样，等于被人提前点破了。
- **代价**：改插件一处（拿 `agent.id` 建索引表）+ 一张 `_会话索引.json`。半小时。

### 2. 「规则落盘只认机主」

- **他们**：只有「机主亲口说的」和「机主明确同意过的」能进规矩。程序输出、体检结论、
  子代理汇报、别的场景发来的建议、自动生成的文件、**自己的推断**——都算不上依据。
- **我们**：MEMORY 现在主要靠我 `memory_note` 往里写，写什么基本由我判断。
- **判断**：抄。这条正好治我最容易犯的病——把「我觉得对」写成「我们说好了」。
- **代价**：PERSONA 加一条，零成本。

### 3. 派单 / 回执 / 不许无限对话

- **他们**：
  - **派单 ≠ 公告**：要对方**动手**才叫派单，必须真投递；只是"知悉"才允许只落盘。
  - **回执必须走投递**：只在自己窗口说"我做完了"不算交付。**「活干完了但对方还不知道」= 没干完。**
  - **禁止无限对话**：一次派单 = 一条回执 = 一条收尾知悉 = 结束。≤200 字、≤10 行、
    首行标记、末行写 `【结束】`。**收到知悉一个字都不许回。**
  - 理由写得很直白：「AI 之间客套起来会互相点燃，一天能烧掉几十万 token。」
- **我们**：协同板刚立，只有格式没有约束力。
- **判断**：抄，这是三条里最值钱的一条——它直接对着我们的余额说话。
- **代价**：写进协同板抬头。十分钟。

## 二、该改（我们已有，但做得不对）

### 4. 判据只能用事实，不能用「我写进去的值」

- **他们**：「判断到位了没有只能看画面，不能看自己写的存储值。」
- **我们**：今晚刚被这条打脸——F5／轮询／WMI 三次都是我"以为好了"，
  最后靠采样 `LastAccessTime` 这种外部证据才切开真相。
- **判断**：不用改结构，但要**把它写成规矩**，别只当教训记着。
- **代价**：PERSONA 半条。

### 5. 注入要有额度，别什么都往每轮里塞

- **他们**：全局铁律控制在 20 KB 上下，细则全部下沉到「规范层」**不注入、按需查**；
  并且明说「攒到 10~15 条就停下，超过这个数就没人读了」。
- **我们**：PERSONA 1996 字 + 定位卡 688 字 + MEMORY 4232 字 ≈ 7000 字，**已经在合理区间**。
- **判断**：保持现状，但把「注入层永远要短」写进规矩，防我以后往里堆东西。
- **代价**：一句话。

## 三、别抄

### 6. 六层结构 / 五场景分工 / 客户交付制

他们那套是**一个人管 20 个场景、接客户、交付项目、收钱**的工作台。
我们是一人 + 四个会话，用它写作业、做《记井》、聊天。**规模差一个量级，硬套只会多维护几张表。**

### 7. 22.7 KB 的全局铁律整份注入

他们自己的副作用表里就写了「注入变长 = 每轮都更贵」。
我们余额 ¥9，每轮多两万字等于成本翻几倍。**只挑条目，不搬原文。**

### 8. 身份索引表 + 面板 pin（Electron 界面那套）

那是他们自己壳里的东西（`sessionTitle` / `sessionId` / `pinTarget` 三个字段钉会话）。
我们的界面是 DSH 自己的，没有这个面板体系，抄不了。

## 四、他们自己承认的坑（值得我们提前防）

- **写回不是可选项**：「漏记的部分仍会丢——我们自己两条会话各写各的，记录数分叉成 15199 / 21272，事后才对上。」
  → 我们要防的是：同一件事被两间各记一份，然后对不上。协同板要写「谁是唯一记录人」。
- **AI 会自己发明规矩**：处理办法是「发现它在自创规矩 ⇒ 要求把它单独列成『待机主确认』」。
  → 我以后新想到的规矩，先列进待确认，不进 PERSONA。
- **最容易劝退的是第一条**：想把所有规矩一次写全。写不全的；
  「每一条 ⛔ 背后都对应一次真事故，事故没发生之前你不会知道要写它。」

---

## 五、我建议的动作（按性价比排）

1. **改认领方式**：标题 → 会话 id + 索引表（半小时，消除一个会安静失效的坑）
2. **协同板加三条硬约束**：派单≠公告 / 回执要投递 / 禁止无限对话（十分钟）
3. **PERSONA 加两条**：规则只认机主 / 判据只能看事实（十分钟）

第 4、5 条（六层结构、界面壳）**不做**，除非哪天我们真的同时跑五件以上的活。
